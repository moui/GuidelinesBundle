# How to log your time

> This is an example guide. An administrator can replace it under **System → Guidelines**.

## Every day

- Log your time **on the same day**, or the next day at the latest.
- If you use the timer, remember to **stop** it when you finish.
- Entries cannot overlap with your other entries.

---

## Customer, project and activity

| If you worked on… | Choose |
|---|---|
| A customer project | That customer's project |
| A meeting or visit for a customer project | The same project, with the activity **Meeting** |
| Support or maintenance for a customer | The customer's **Support** project |
| A proposal, estimate or demo | The customer's **Pre-sales** project (non-billable) |
| Internal work: email, planning, team meetings | Your team's **Internal** project |
| Courses and conferences | The **Training** project |

Put the details (which module, which ticket, which topic) **in the description**, not in the
project name. If the project you need is missing, ask for it before logging the time somewhere else.

---

## Description

The description should say **what you did**, so that someone else understands it without asking you.

| Not like this | Like this |
|---|---|
| `Work`, `Misc`, `.` | `Fixed the date filter in the monthly sales report` |
| `Meeting` | `Weekly follow-up with the customer about the data migration` |
| `Support` | `Ticket #482: map viewer did not load; restarted the service` |
| `Training` | `Online course on accessibility, module 3 of 5` |

If you could not tell what you did a month from now by reading it, add more detail.

---

## Billable

Do not change it by hand: the project decides it.

---

## Absences and holidays

- Absences are **not logged as working time**. Record them where your company asks you to
  (for example, Kimai's absences or your HR tool).
- On that day, log only the hours you actually worked.
- Tell your manager **before** taking days off.
